# 다국어(5개 언어) 설계

> 작성일: 2026-11-17. 프론트가 지원하는 언어(`frontend/i18n.mjs` `locales`)와 같은 5개: `ko`(원본), `en`, `zh`, `vi`, `uz`.

## 1. 원칙

1. **한국어가 원본이다.** 다른 언어는 한국어 문구의 번역이다. 문진 질문·규칙·진료과 판단은 언어와 상관없이 같다(코드·ID는 그대로).
2. **번역이 없으면 그 문구만 한국어로 낸다.** 프론트는 `label.<locale>`이 없으면 `ko`를 보여 준다. 엔진은 없는 번역을 지어내지 않는다.
3. **요약은 섞지 않는다.** 한 언어의 요약에 필요한 번역이 하나라도 없으면 그 언어의 요약은 만들지 않는다(한국어 요약이 보인다). 한 문단 안에 두 언어가 섞이지 않게 하기 위해서다.
4. **안전 문구는 사람 검토 대신 장치로 지킨다(11/18 변경).** 응급·위기 안내(119·109·112·1366 문구와 그 덧붙임 문장), 위험 확인 질문(`RISK_CONFIRM`), 민감 안내 선택(`SENSITIVE_CHOICE`), 요약의 응급 관련 줄도 검토 상태(`draft`·`team_reviewed`)와 상관없이 번역을 낸다. 대신:
   - 모든 번역의 숫자(전화번호·24시간·기간)가 원문과 같아야 한다. 빌드(`06f`)가 막고 테스트가 다시 확인한다.
   - 프론트 응급 카드는 번역 아래에 한국어 원문을 함께 보인다(119·주변 사람에게 보여 줄 수 있게). 번역이 틀려도 원문이 남는다.
   - 전화번호(119·109·112·1366)는 한국 기준 그대로 두고, 기관명 해바라기센터는 번역 뒤 괄호에 한국어를 둔다.
   - `review_status`는 검토 기록용으로 남긴다(동작에는 쓰지 않음).
5. **번역은 데이터다.** 번역은 한 곳(번역 표 `ref.text_i18n`)에만 둔다. 기존의 빈 칸 `text_en`·`display_en`은 쓰지 않는다(값이 없고, 두 곳에 나뉘면 어긋난다).
6. **번역이 원문을 따라가는지 검사한다.** 번역 행마다 그때의 한국어 원문(`source_ko`)을 함께 둔다. 원문이 바뀌었는데 번역이 그대로면 그 번역은 쓰지 않고(한국어로 냄) 빌드·테스트가 알린다.
7. **입력 언어의 한계를 숨기지 않는다.** 위험 표현 규칙과 증상 사전은 한국어 문장만 인식한다. 외국어 입력의 위험 감지는 이 작업 범위 밖이며(6단계), 그 전까지 화면에 "증상은 한국어로 입력해 주세요"를 5개 언어로 보인다.

## 2. 번역 표 `ref.text_i18n`

| 칸 | 뜻 |
|---|---|
| `target` | `item`(문진 질문) · `option`(선택지) · `symptom`(증상 이름) · `department`(진료과 이름) · `template`(엔진 문구) |
| `key` | `item`: link_id(`Q0`) / `option`: `link_id:code`(`Q0:yes`) / `symptom`: symptom_id / `department`: dept_id / `template`: 엔진 문구 키(`risk_confirm.question`) |
| `locale` | `en`·`zh`·`vi`·`uz`(`ko`는 원본이라 넣지 않음) |
| `text` | 번역 문구(300자 이하, 요약 줄은 2000자 이하) |
| `source_ko` | 번역할 때의 한국어 원문(원칙 6) |
| `review_status` | `draft` · `team_reviewed` |
| `data_version` | 다른 ref 표와 같은 버전 |

- 기본 키: (`target`, `key`, `locale`).
- 원본 파일: `data_pipeline/config/i18n_v1.csv`(사람이 고치는 넓은 표: 원문 한 줄에 4개 언어). 빌드가 시드 `text_i18n.csv`(긴 표)를 만든다. 엔진은 시드 CSV 또는 Supabase 표를 읽는다(다른 ref 표와 같은 길).
- 문구 안의 자리 표시(`{0}`)는 번역에도 그대로 있어야 한다(예: 통증 점수, 진료과 순위).

## 3. 엔진 동작

- 질문·선택지·증상·진료과·엔진 문구를 `{ko, en?, zh?, vi?, uz?}` 한 객체로 보낸다. 사용자가 언어를 바꾸면 프론트가 다시 묻지 않고 바로 바꿔 보여 준다.
- 요약은 언어마다 따로 만들어 같은 객체에 담는다(원칙 3).
- 응급 안내 덧붙임(109·112·1366 한 문장)도 언어마다 붙인다. 그 언어의 덧붙임이 없으면 그 언어의 안내 전체를 내지 않는다(한국어 안내가 보임).
- 응답 계약 검사는 5개 언어 키를 허용한다.

## 4. 진행 순서

1. 원칙(이 문서) → 2. 번역 표(CSV·마이그레이션·적재 목록) → 3. 번역 초안(전부 `draft`)·팀 검토 → 4. 엔진 → 5. 프론트 확인 → 6. 외국어 입력 안내 → 7. 검증

## 6. 번역을 고치거나 검토하는 법

1. `data_pipeline/config/i18n_v1.csv`에서 번역 칸(en·zh·vi·uz)을 고친다. 누가 확인했으면 `review_status`를 `team_reviewed`로 바꿔 기록한다(동작은 같음).
   - 안전 문구(`template` 중 `emergency.*`, `addon.*`, `not_diagnosis`, `q.risk_confirm.*`, `q.sensitive_choice.*`, `summary.riskUnconfirmed`·`safetyUnanswered`·`footer`·`emergencyHeader`)를 고칠 때는 전화번호·숫자를 빼거나 바꾸지 않는다(빌드가 막는다).
2. 한국어 문구(시드·`templates.mjs`)를 바꾸었으면 먼저 `care_engine`에서 `node scripts/i18n_sync.mjs` → 원문이 바뀐 행이 알려진다. 그 행은 번역을 다시 고친다(그 전까지 그 문구는 한국어로 나온다).
3. `data_pipeline`에서 `python pipeline/06f_build_i18n_seed.py`(검사 + 시드 `text_i18n.csv`) → `python pipeline/06b_load_supabase.py --dry-run` → 적재.
4. `care_engine`에서 `npm test`(번역 빠짐·낡음 검사 포함).
