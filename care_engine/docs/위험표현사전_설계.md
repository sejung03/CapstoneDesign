## 1. 왜 필요한가

- 엔진의 안전 규칙은 지금 **선택형 답(Q0, N1~N3)에만** 걸린다. 사용자가 대화창에 쓴 "가슴이 쥐어짜듯 아파요" 같은 위험 표현은 알아보지 못한다.
- 독립 검토(S1)에서 "쓰러졌어요 병원 어디" 같은 문장이 응급 확인 없이 검색으로 넘어가는 문제가 나왔다. EF 보완의 `riskCues`는 **지름길만 막는 임시 조치**이고 응급 판정은 하지 않는다.
- 위험 표현 사전은 자유 입력을 **규칙으로**(LLM 없이) 응급 안내에 연결한다. 시연 전 필수.

### 2-1. ① 기준 — 국내 공식 자료 두 가지를 겹쳐 쓴다

**A. 응급의료에 관한 법률 시행규칙 [별표 1] 「응급증상 및 이에 준하는 증상」** (보건복지부령)
- **[근거]** 법정 응급증상 목록이다. 응급실 이용 시 건강보험 혜택을 가르는 기준으로도 쓰인다. 법령이라 저작권 보호 대상이 아니다(저작권법 제7조).
- 응급증상 분야와 항목(요지):
  | 분야 | 항목 |
  |---|---|
  | 신경학적 | 급성 의식장애, 급성 신경학적 이상, 구토·의식장애 등이 있는 두부손상 |
  | 심혈관계 | 심폐소생술이 필요한 증상, 급성 호흡곤란, 심장질환으로 인한 급성 흉통, 심계항진, 박동이상 및 쇼크 |
  | 중독·대사 | 심한 탈수, 약물·알코올 등의 과다 복용이나 중독, 급성대사장애 |
  | 외과적 | 개복술을 요하는 급성 복증, 광범위한 화상, 관통상, 개방성·다발성 골절 등, 사지 절단 우려 혈관손상, 다발성 외상 |
  | 출혈 | 계속되는 각혈, 지혈이 안 되는 출혈, 급성 위장관 출혈 |
  | 안과적 | 화학물질에 의한 눈 손상, 급성 시력소실 |
  | 알러지 | 얼굴 부종을 동반한 알러지 반응 |
  | 소아과적 | 소아경련성 장애 |
  | 정신과적 | 자신 또는 다른 사람을 해할 우려가 있는 정신장애 |
- "이에 준하는 증상"(현훈, 과호흡, 배뇨장애, 8세 이하 소아 38℃ 이상 고열 등)도 같은 별표에 있다.
- 원문은 국가법령정보센터에서 시행일 기준으로 다시 확인해 `evidence`에 조문·시행일을 적는다.

**B. 119구급상황관리센터 상담 매뉴얼** (소방청)
- **[근거]** 소방청 사전정보공개 게시물(2018-05-21 게시), **공공누리 제1유형**(출처표시). 실제 신고 접수에서 구급 상황이면 이 매뉴얼의 도입부 수보 프로토콜을 쓴다(이규환 외 2016).
- Ⅱ장 도입부: 의식·호흡·심정지 확인 질문과 **조기 긴급출동 상황 목록**. Ⅲ장: 범주 33개마다 **중증도(긴급/응급/비응급) 기준**.
- 신고 전화를 받는 쪽 기준이라 **일반인 표현에 가장 가깝다.** 별표 1은 의학 용어라 표현을 만들 때 매뉴얼을 함께 본다.

**C. 비응급 경계 — 119구조·구급에 관한 법률 시행령 제20조** (소방청 소관)
- **[근거]** 구급대원이 출동을 거절할 수 있는 비응급환자: 단순 치통, 단순 감기(38℃ 이상 고열 또는 호흡곤란 제외), 생체징후가 안정된 타박상 등.
- 쓰는 곳: **위험 표현으로 넣지 않을 것**을 정하는 경계, 그리고 평가셋의 "음성(응급 아님)" 예시. 예외 문구("고열 또는 호흡곤란이면 제외")는 위험 표현 쪽에 넣는다.

## 3. 만드는 원칙

1. **놓치지 않는 쪽 우선.** 과잉 안내가 누락보다 낫다. 단, 바로 응급 종료는 2-3표 첫 줄에 해당하는 표현만.
2. **규칙으로만.** 응급 판정에 LLM을 쓰지 않는다(기존 결정).
3. **국내 공식 기준에 있는 것만.** 항목마다 별표 1 조문 또는 매뉴얼 범주·쪽을 `evidence`로 단다. 근거 없는 항목은 넣지 않는다.
4. **부정·다른 사람·과거 표현**은 v1에서 **걸리게 둔다**(§7-3). 평가셋으로 오탐을 재고 조정한다.
5. **원문 보호.** 걸린 원문은 로그·trace에 남기지 않고 `rule_id`만.
6. **검토 방법.** 의료진 검토는 하지 않는다(2026-11-17 결정). 대신 ① 항목마다 공식 기준(별표 1 조문, 매뉴얼 범주·쪽) 대조, ② 새 세션 독립 검토, ③ 평가셋으로 누락·오탐 측정을 필수로 한다. 위험 표현 사전은 LLM을 쓰지 않으므로 OpenAI 이용 정책과는 관계없다.

## 4. 데이터 형식

`care_engine/engine/rules/free_text_v1.json` 한 파일(§7-4)
```json
{
  "version": "free-text-v1",
  "rules": [
    {
      "rule_id": "FT-CARDIO-01",
      "priority": 5,
      "patterns": ["정규식(정규화한 공백 없는 메시지 기준)"],
      "result": "URGENT_NOTICE",
      "terminal": true,
      "triage_category_id": 17,
      "message_key": "urgent_notice_chest_pain",
      "evidence": {
        "source": "emergency_act_rule_annex1",
        "ref": "응급의료법 시행규칙 별표1 심혈관계 '심장질환으로 인한 급성 흉통' (시행일 YYYY-MM-DD)",
        "manual_119": {"category": 17, "page": 0, "level": "긴급"}
      },
      "review_status": "draft"
    }
  ]
}
```
- `priority` 1~9는 자유 입력 규칙 전용. EMERGENCY_STOP 규칙이 URGENT_NOTICE보다 작은 번호(먼저).
- `evidence.source`: `emergency_act_rule_annex1`(별표 1) 또는 `manual_119`. 둘 다 해당하면 둘 다 적는다.
- `message_key`마다 안내 문구는 `engine/templates.mjs`에 추가(초안 → 팀 검토). 109 문구 키 `crisis_notice_109` 추가.
- 엔진 로더가 이미 형식을 검사한다(rule_id, priority 범위, 패턴 컴파일, 필수 칸).

## 6. 참고만 할 자료
- **Pre-KTAS(병원 전 응급환자 중증도 분류기준)**: 소방청·복지부·국립중앙의료원·대한응급의학회가 만든 5단계(소생~비응급) 기준. 2024년부터 법적 근거를 갖추고 시행. 현장 구급대원이 활력징후로 판단하는 도구라 자유 입력 사전에 그대로 쓰기 어렵고, 세부 기준의 공개·이용 조건은 **[확인 필요]**. 기준표를 만들 때 분류가 크게 어긋나지 않는지 비교용으로만.
- **KTAS(응급실 분류)**: 같은 이유로 비교용. 내용은 옮기지 않는다.
- 일본 소방청 자료는 쓰지 않는다(국내 기준이 있음).

## 7. 결정 (2026-11-17, 팀원 1 결정)

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| 1 | 자해·자살 **생각** 표현의 결과 | **새 결과 종류를 만들지 않고** `URGENT_NOTICE`(terminal) + 109 문구(`crisis_notice_109`). **행동**(이미 함·하는 중·약을 삼킴)은 `EMERGENCY_STOP` | 별표 1이 "자신 또는 다른 사람을 해할 우려가 있는 정신장애"를 **응급증상**으로 정함. 과다 복용·중독도 응급증상. 프론트 계약(`emergency` 객체)을 바꾸지 않아도 되어 안정적 |
| 2 | URGENT_NOTICE의 terminal | **true 유지** | 별표 1 응급증상은 응급실 대상이라 동네 의원 진료과 안내가 맞지 않음. 교차 검토 권고("필수 정보가 없으면 비응급으로 단정하지 말 것")와 같은 방향. 이미 데이터·엔진이 true로 동작 중이라 바꾸지 않는 것이 안정적 |
| 3 | 부정 표현 처리 | **v1은 부정이 붙어도 걸리게 둔다**(부정 제외 규칙 없음) | 사실 확인(B §4-2)에서 단순 부정 규칙이 "안 멈춰요" 같은 양성 문장을 잘못 뺐음. 위험 표현에서 잘못 빼면 응급을 놓친다. 오탐은 평가셋(R4)으로 재고, 근거가 생기면 좁은 예외만 추가 |
| 4 | 원본 형식 | **JSON 한 파일**(`free_text_v1.json`), YAML 원본·생성 단계 없음 | 엔진 로더가 이미 이 형식을 검사함. 원본이 하나라 변환 오류가 없음. 근거는 `evidence` 칸에 둔다 |
| 5 | 장윤희 논문 이용 범위 | **인용과 표현 유형 참고만**, 목록을 옮기지 않음 | 이용 조건 확인 결과와 상관없이 안전. 표현 자체는 매뉴얼(공공누리 제1유형)과 팀 작성으로 만든다 |
| 6 | *(11/17 RF)* 확인 질문(검토 I7) | **중간안**: `freetext_urgent`만 확인 질문. 범위는 질문 ID `RISK_CONFIRM_<n>`(n = 질문할 때의 사용자 메시지 수)로 상태 없이 계산하고, 메시지 j의 hit는 n>j인 답이 덮는다(여럿이면 예 > 잘 모르겠어요 > 아니요). 같은 범위 질문은 최대 2번 | 한 번 걸리면 대화 끝까지 응급만 받던 문제(오탐·부정·과거 언급). EMERGENCY_STOP은 놓치는 쪽이 더 위험해 그대로 |
| 7 | *(11/17 RF)* 민감 안내 비수집 | 109·112·1366은 확인 질문·문진·LLM 없이 기관 안내만(terminal). 응답에 followUp·search·진료과·summary·profileUpdates 없음. trace에는 `{kind:"sensitive_referral"}`만(rule_id·message_key·메시지 위치·다른 hit 없음). 함께 걸린 민감 hit는 EMERGENCY_STOP 응답에서도 trace에 남기지 않음 | 서비스 본 목적이 아니고 매우 민감한 정보. 엔진 밖(프론트 대화 저장·사용자 DB)은 팀 합의 필요 |
| 8 | *(11/17 RF)* 문맥 제외 원칙 | 메시지 전체 제외(`^(?!.*X)`)를 쓰지 않는다. 제외는 애매한 단어 **바로 앞뒤(약 8자, 필요하면 더 좁게)** 쓰임으로만 | 전체 제외가 "축구 보다가 아이가 경기를 일으켰어요" 같은 진짜 응급을 놓쳤다. 평가셋 mixed_context로 확인 |
