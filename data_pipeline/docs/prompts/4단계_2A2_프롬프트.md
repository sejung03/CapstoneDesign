# 4단계 + 2A-2 프롬프트: 진료과 이름 정리 → 경로 A 계산 → 두 경로 합치기

> 사용 순서
> 1. **S4-1 (Claude Code)**: AI Hub 진료과 표기 목록과 라벨링 입력 만들기 → 멈춤
> 2. **S4-2 (라벨링)**: 같은 지시문을 Claude Code 새 세션과 Codex에서 각각 실행
> 3. **S4-3 (Claude Code)**: 라벨 합치기 → `department_alias` → 경로 A 계산 → 멈춤
> 4. **2A-2 (Claude Code)**: 두 경로 합치기 → 최종 진료과 추천
>
> 방법은 지금까지와 같다: 표기 정리는 닫힌 목록에서 두 평가자가 따로 고르고 일치할 때만 채택, 계산은 규칙으로.

## S4-1 — Claude Code: 진료과 표기 목록

```
4단계를 시작한다. S4-1까지만 하고 멈춰서 보고해.
원칙은 지금까지와 같다(원본 읽기만, 멱등, utf-8-sig, reports/에 AI Hub 문장 금지, 팀 내부 문서(확정사항 및 방법론) 수정 금지).

1. AI Hub "증상" 답변(data/interim/v3/symptom_answers.csv)의 department_raw에 나온 진료과 표기를 모두 모은다.
   - 줄바꿈("\n")으로 붙은 값은 나눠서 각각 센다.
   - 표기마다 n_answers, n_diseases
   - 출력: data/interim/v4/dept_raw_values.csv
2. 선택지: data/interim/v4/label_options_dept.csv
   = 2A에서 쓰는 표준 진료과 목록(심평원 의원급 표시과목 기준, 치과 계열은 "치과" 하나) + DROP(진료과가 아님) + AMBIGUOUS
3. 라벨링 규칙: data/interim/v4/labeling_guide_dept.md
   - 각 표기를 표준 진료과 하나로 고른다. 오타·옛 이름(비뇨기과→비뇨의학과, 정신과→정신건강의학과,
     일반외과→외과, 흉부외과→심장혈관흉부외과)은 해당 표준 과로.
   - 세부 분과(소화기내과, 순환기내과 등)는 상위 과(내과)로.
   - 진료과가 아닌 값(질환명, "안경" 등)은 DROP.
   - 진단계 과(영상의학과, 영상진단의학과, 방사선과, 병리과, 진단검사의학과, 핵의학과)와 의학유전학과는 해당 과로 고르되,
     2A의 제외 진료과 규칙으로 추천에서 빠진다는 점을 note에 적지 않아도 된다(규칙이 처리).
   - 둘 이상에 걸치면 AMBIGUOUS, note에 후보를 모두 적는다.
   - 출력 컬럼: raw_value, dept, note

보고: 고유 표기 수, 상위 30개(표기, n_answers), 선택지 수
```

```
data/interim/v4/labeling_guide_dept.md를 읽고 data/interim/v4/dept_raw_values.csv의 모든 표기를 라벨링해.

- 출력: data/interim/v4/labels/{TOOL}/dept.csv
- data/interim/v4/labels/ 아래 다른 폴더는 열지 마. 스크립트로 자동 분류하지 말고 하나씩 직접 판단해.
끝나면 DROP·AMBIGUOUS 개수만 알려줘.
```

## S4-3 — Claude Code: department_alias와 경로 A

```
S4-2 라벨(labels/claude/dept.csv, labels/codex/dept.csv)로 진료과 정리표를 만들고 경로 A를 계산해. 끝나면 멈춰서 보고해.

1. 합치기(T1과 같은 후보 집합 규칙): 각 평가자의 후보 집합 = 고른 dept 하나, AMBIGUOUS면 note의 후보들.
   교집합이 1개 → 그 과로 채택 / 2개 이상 → span(그 과들에 1/n씩 나눠 셈) / 0개 → 채택하지 않음(계산에서 뺌).
   출력: data/processed/v4/department_alias.csv (raw_value, dept, status, claude, codex)
2. 질환별 진료과 → data/processed/v4/disease_department.csv
   - 질환의 모든 "증상" 답변(필요하면 다른 intention 답변도 같은 질환이면 포함 — 포함 여부를 보고에 적기)에서
     department_raw를 alias로 바꿔 집계: 질환마다 진료과별 답변 수와 비율(share), 순위
   - DROP·미채택 표기는 빼고, 한 답변에 같은 과가 두 번 나오면 1번만 센다.
3. 경로 A: 증상별 진료과 → data/processed/v4/symptom_department_path_a.csv
   - disease_symptom.csv에서 kept인 (질환, 증상) 쌍만 사용
   - score(증상, 과) = Σ_질환 [ 그 질환에서 증상 share × 그 질환의 과 share ]  → 증상 안에서 합이 1이 되게 정규화
   - n_diseases_linked(그 증상에 연결된 kept 질환 수)를 같이 남긴다
   - path_a_ok = n_diseases_linked ≥ 3 (기준값은 config/recommend.yaml의 path_a.min_diseases)
4. 교차검증 미리보기(파일 수정 없이 보고):
   - 경로 B 추천이 있는 증상 중 경로 A 1위와 경로 B 의원급 1위가 같은 비율
   - 다른 증상 목록 상위 20개

보고: alias 채택/미채택 수, 질환별 진료과가 0개인 질환 수, path_a_ok 증상 수, 교차검증 결과
```

## 2A-2 — Claude Code: 두 경로 합치기

```
경로 A(symptom_department_path_a.csv)와 경로 B(2A-1 결과)를 합쳐 최종 진료과 추천을 만든다.
입력 증상 목록은 standard_symptoms_v2_1.csv로 바꾼다(config/recommend.yaml의 symptoms_file).

1. 증상마다 쓰는 경로(path_used) — 2026-11-12 결정: "경로 B가 후보를 정하고, 경로 A는 순서만 정한다"
   - 이유: 교차검증 일치율 62%. 경로 A는 AI Hub 라벨이 "내과"에 쏠려 있어(세부 분과까지 내과로 합쳐짐) 단독으로 쓰면 내과가 과하게 나온다.
     경로 B는 실제 청구 기반이라 후보 과의 범위가 현실적이다.
   - B: hira_indistinct=false 이고 path_b_used=true → 경로 B 순위 그대로(지금까지의 규칙 유지)
   - B(보완): hira_indistinct=true 이지만 path_a_ok=false 이고 await_path_a가 아니면 → 경로 B 추천 그대로
   - B+A: hira_indistinct=true 이거나 await_path_a 이고 path_a_ok=true →
       후보 = 경로 B 전체 순위(JSON)에서 의원급 share ≥ 0.05 인 과 ∪ 병원급 share ≥ 0.10 인 과(제외 과 뺀 뒤)
       후보를 경로 A 점수 순으로 다시 정렬(경로 A 점수가 0인 후보는 B 순서대로 뒤에)
       rec1~3은 이 순서에서 뽑고, 2·3순위 최소 비율 규칙은 경로 B share 기준으로 그대로 적용
       단, 경로 A가 고른 1위가 경로 B에서 의원급 ≥ 0.20 또는 병원급 ≥ 0.10 이 아니면 rec1은 경로 B 1위를 유지하고
       경로 A 순서는 rec2·rec3에만 쓴다
   - A: 경로 B 순위 자체가 없는 증상(새 증상 등에서 B 계산이 안 된 경우)만 path_a_ok면 경로 A 단독
   - none: 위 어느 것도 안 되면 추천 비움 + fallback=true
   - is_injury(모든 증상에 계산, 규칙은 config/recommend.yaml의 fallback 절):
     119 범주 19,20,22,23,26,28,29,30,31과 연결된 증상, 또는 ICPC 코드 S12~S19 → true
     (21 눈 손상/질환, 24 익수, 25 일산화탄소, 27 중독은 제외)
   - fallback_departments.csv(data/processed/v4/):
     · injury: is_injury=true이면서 path_used가 B·B+A·A인 증상들의 최종 rec1을 모아 많이 나온 순서 상위 3개 과
     · general: 내과, 가정의학과 (고정). 응급의학과는 넣지 않는다(응급 신고 버튼이 처리)
   - 새 증상 34개도 먼저 2A(경로 B) 계산을 돌려 순위 JSON을 만든 뒤 위 규칙을 적용한다
   - 생식기·직접 지정 규칙으로 정한 rec1은 경로와 관계없이 유지
2. 경로 A 순위에도 같은 후처리 규칙을 적용(제외 진료과 목록에 의학유전학과·방사선종양학과 포함 확인, 없으면 추가): 제외 진료과, 치과 범위, 성별(남성 증상의 산부인과),
   생식기 규칙, 2·3순위 최소 비율(경로 A는 의원급/병원급 구분이 없으므로 10% 하나로)
3. 교차검증 컬럼: top_a, top_b, agree(둘 다 있을 때)
4. 출력: data/processed/v4/symptom_department_final.csv
   (symptom_id, name_ko, path_used, rec1~3, rec1~3_share, top_a, top_b, agree, dept_rule, fallback, pediatric_top, er_share)

보고 → reports/2A2_build.md
- path_used별 증상 수(B / A / none)
- 상식 점검 20개 + D20 하위 4개 + 2A-1에서 비었던 21개의 최종 rec1~3
- agree=false인 증상 목록 (경로 B를 쓴 증상 중 A와 1위가 다른 것)
- fallback 증상 목록(is_injury 포함)과 fallback_departments.csv 내용
```
