# 의료 안내

> 5개 언어 UI가 추가되었습니다. [다국어 안내](docs/I18N.md)를 확인하세요. 화면은 저장된 번역 파일을 사용하며 실행 중 Gemini API를 호출하지 않습니다.

> Supabase 로그인·행동 온톨로지 연결 코드가 추가되었습니다. 원격 SQL 적용과 카카오 공급자 설정은 [연결 안내](docs/SUPABASE.md)를 확인하세요. 아래 과거 버전 설명의 미연결 항목 중 로그인·행동 설정·즐겨찾기는 이 안내를 우선합니다.

증상을 정리하고 병원과 약국을 찾는 웹 앱입니다. Next.js App Router와 React를 사용하며, 기존 디자인과 문진·지도·분석서 동작을 유지합니다. 대화를 기본 화면으로 제공하며 지도는 조절 가능한 패널, 내 정보는 단독 화면으로 엽니다. 내 정보에서는 건강정보와 즐겨찾기를 관리합니다. 내 정보에서 저장한 건강정보만 PDF로 출력합니다. 문진과 대화 내용은 포함하지 않습니다. 로그인 진입도 내 정보 안에 있습니다. 실제 LLM 서버는 아직 연결하지 않았습니다.

## 실행

Node.js 24 LTS 최신 버전(24.15 이상)을 권장합니다. Node.js 22는 22.22.2 이상이 필요합니다. VS Code의 CMD 터미널에서 실행합니다.

```cmd
cd /d D:\Projects\capstone-medical\frontend
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:3080 에 접속합니다. 카카오 SDK 도메인도 이 주소와 포트를 등록합니다. 다른 포트는 `npm run dev -- --port 3081`로 지정합니다. 이전 서버의 자동 다음 포트 선택 기능은 Next.js 실행에는 적용되지 않습니다.

로컬 설정은 `.env.local` 하나로 관리합니다. 처음 설치할 때만 `.env.example`을 `.env.local`로 복사하고 키를 입력합니다. 기존 `.env.local`을 예제 파일로 덮어쓰지 마세요. GitHub에는 실제 키가 없는 `.env.example`만 올립니다.

## 업데이트 적용

실행 중인 서버를 Ctrl+C로 종료합니다. 기존 `frontend` 폴더는 백업 이름으로 바꾸고, ZIP의 `frontend` 폴더를 `D:\Projects\capstone-medical\frontend`에 새로 놓습니다. 이전 폴더의 `.env.local`만 새 폴더로 복사합니다. 개인 수정 파일과 `.git`이 있다면 먼저 별도로 보존하세요. `node_modules`, `.next`는 옮기지 않습니다.

```cmd
cd /d D:\Projects\capstone-medical\frontend
npm ci
npm run check
npm run dev
```

0.14.0에는 PDF 읽기 의존성이 추가되어 `npm ci`가 필요합니다. PDF worker와 한글 CMap 등은 실행/빌드 전에 자동으로 준비됩니다.

## 유지된 기능

- 증상 또는 약국 찾기 선택지와 직접 입력으로 대화를 시작합니다. API 연결 시 대화 안에서 질문·선택지를 받아 문진하며, 미연결 시 기존 문진 1·2 화면을 사용합니다. 실제 질문과 분류는 팀원이 제공합니다.
- 열린 대화 패널, 선택적 응답 어댑터, 상황 요약 확인과 분석서 반영.
- 카카오맵, 검색 후보 즉시 검색, 병원·약국 필터, 가까운 운영 중 대안 비교.
- 실제 위치 검색, 지도 위치 재검색, 등록 운영시간과 오늘 요일 강조.
- 이동 거리와 버튼으로 펼치는 길찾기, 주소·전화번호 복사.
- 분석서 편집·복사·인쇄/PDF, 한국어·영어, 라이트·다크, 반응형 화면.

문진, 건강정보, 대화와 분석서는 계정이나 서버에 저장하지 않습니다. 검색 지역·정렬은 사용자가 별도 저장 옵션을 선택한 경우만 브라우저에 보관합니다. 실제 로그인 연동, 방문 이력, 공유 링크와 QR, 방문 평가는 아직 구현하지 않았습니다. 로그인 진입 화면과 서비스 약관·개인정보 동의 화면은 제공합니다.

## 검증과 배포

```cmd
npm run check
npm run build
npm run check:next
npm start
```

`check`는 기존 회귀 테스트와 Next API 변환·수명주기 테스트입니다. `check:next`는 빌드 결과를 실제 Next 서버로 실행하여 HTTP 응답, CSP, 공개 자산과 비공개 소스 차단을 확인합니다. 또한 jsdom에서 실제 React 번들을 실행하고 모의 SDK/API로 문진, 검색, 상세, 길찾기, 복사, 분석서 편집, 테마와 언어 전환을 검사합니다. jsdom은 테스트 전용 의존성이며 화면 라이브러리가 아닙니다. 외부 카카오·공공데이터 연동 성공을 보장하는 테스트는 아닙니다.

배포는 Node.js 서버를 실행하는 방식 또는 Next.js 서버 기능을 지원하는 호스팅을 사용합니다. GitHub Pages와 정적 export만으로는 운영시간·길찾기 서버 API를 제공할 수 없습니다. 배포 환경에 서버 환경변수를 등록하고 `npm ci`, `npm run build`, `npm start`를 실행합니다. 서버 호스팅에서 외부 접속이 필요하면 `npm start -- --hostname 0.0.0.0 --port 3080`을 사용합니다.

기존 app.js는 상태, 요청 취소, API와 지도 연결, 동작 이벤트를 관리합니다. 운영 화면 마크업은 React가 생성하며, 기존 문자열 렌더러는 이전 회귀 테스트에만 남겨 두었습니다. 대화를 중심으로 배치하고 기존 검색·상세·길찾기와 분석서 기능을 확장 패널에 유지합니다.

레이아웃 스타일은 workspace.css에 분리했습니다. 기존 styles.css와 ui.css 및 폰트는 유지합니다. 패널 확대와 닫기, 모바일에서 대화로 복귀, 새 대화와 문진 중간 건너뛰기를 지원합니다.

### 0.9.1 화면 보완

- 패널 내부의 중복 탐색 메뉴 제거. 채팅 카드의 상세정보와 길찾기는 각각 전용 패널로 표시합니다.
- 헤더와 본문 높이를 분리하고 채팅 카드의 강제 축소를 방지합니다.
- 채팅 추천은 등록된 운영시간상 운영 중인 기관만 기본 직선거리순으로 표시합니다. 시간이 없거나 진료 종료인 기관은 전체 검색에서 확인할 수 있습니다. 실제 임시 휴진 여부를 보장하지 않습니다.

### 0.9.2 길찾기 호출 및 채팅 표시

- 채팅 상세정보와 길찾기를 대화 안에서 펼칩니다. 길찾기는 작은 지도에 API가 반환한 경로 선을 표시합니다. 경로 좌표가 없는 응답에는 임의의 직선을 그리지 않습니다.
- 검색, 상세정보, 가까운 대안 탐색에서 경로를 미리 조회하지 않습니다. 길찾기를 누른 기관의 선택 이동수단만 조회하며 유효한 캐시는 재사용합니다. 일반 화면 갱신으로 만료된 경로를 반복 요청하지 않습니다.
- 길찾기 전에는 직선거리를 표시하고 시간은 표시하지 않습니다. 기본 거리순 정렬은 전체 후보의 직선거리 기준이며, 가까운 대안의 실제 이동거리 비교는 이미 조회된 경로 정보 범위에서만 가능합니다. 전체 기관을 이동 거리로 비교하기 위한 자동 호출은 제거했습니다.

### 0.9.3 카드 내부 표시

채팅의 상세정보와 길찾기는 선택한 병원 카드 안에서 펼칩니다. 펼친 동안 카드 순서를 유지하며 다른 카드 선택 시 한 곳만 펼칩니다. 자동 경로 조회 금지 정책은 유지합니다.

### 0.10.0 추천 순위 연결 준비

선택적인 rankFacilities 요청 함수를 연결하면 실제 검색된 운영 중인 기관의 ID에 한해 추천 순서와 이유를 채팅 카드에 표시합니다. 기본 실행에는 실제 LLM 서버나 임의의 추천 결과를 포함하지 않습니다. 실패 시 기존 결과를 유지하고 오래된 응답과 후보 외 ID는 제외합니다. 연결 형식은 docs/BACKEND.md를 확인하세요. 길찾기 사전 호출 금지 정책을 유지합니다.

### 0.11.0 응급 도움

채팅에서 응급 도움을 열어 119 전화 링크와 위치 확인을 사용할 수 있습니다. 위치 확인은 별도 클릭 시에만 실행하며 신고나 위치 전송을 자동 수행하지 않습니다. 기존 requestAssistant 응답의 emergency 데이터를 받아 안내 문구와 유튜브 영상 ID를 표시하도록 준비했습니다. 실제 응급 판단과 영상 선정은 팀에서 담당하며 기본 실행에 임의의 영상이나 판단 규칙은 포함하지 않습니다.

### 0.11.1 응급 위치 직접 입력

GPS가 없거나 부정확할 때 주소/건물명을 직접 입력해 표시하고 지도에서 검색할 수 있습니다. 자동 주소와 구분하며 GPS 재조회로 덮어쓰지 않습니다. 입력값은 이번 대화 메모리에만 유지합니다.

### 0.12.0 응급 위치 지도와 안내 표시

응급 도움 안에서 지도 클릭/이동/핀 드래그로 위치를 정하고, 주소 입력 시 장소와 주소 검색 후보를 표시합니다. 후보 선택은 같은 지도에 반영하며 외부 지도 검색 버튼은 제거했습니다. 소방청 신고 안내와 선택 가능한 질병관리청의 심폐소생술 교육 영상을 제공하고, 상황별 안내 순서는 백엔드의 emergency.instructions로 받을 수 있습니다. 기본 자료는 emergency-resources.mjs에서 관리합니다. 위치 선택은 병원 검색과 길찾기를 시작하지 않습니다.

### 0.13.0 건강정보 처리 안내

문진과 증상 채팅 시작 전에 공통 안내 카드를 표시합니다. 같은 상담에서 확인 상태를 공유하며 병원 검색과 119 연락은 별도로 이용할 수 있습니다. 현재 상담 동의는 화면에서 실제 처리하는 항목과 세션 기간을 안내합니다. 외부 adapter는 검토된 healthNotice와 해당 범위의 확인 없이는 건강정보 요청을 보내지 않습니다. 실서비스 문구 검토, 서버 측 검증과 동의 증빙 저장은 별도 작업입니다. 이전 분석서 가져오기도 같은 처리 안내를 거칩니다. 외부 연결 시에는 가져온 기록을 포함하는 범위를 별도로 설정해야 합니다.

### 0.14.0 이전 분석서로 이어가기

대화의 **이전 분석서로 이어가기**에서 PDF를 선택하거나 복사한 내용을 붙여넣습니다. 브라우저에서 읽은 내용을 수정하고 확인한 뒤 참고 자료로 사용합니다. 현재 문진·증상·내 정보를 자동으로 덮어쓰지 않습니다. 실제 AI 후속 문진은 백엔드 연결 후 제공됩니다.

PDF는 이 서비스의 제목이 포함된 텍스트 PDF만 지원합니다(5MB, 20쪽, 20,000자 이하). 스캔본·암호화 파일은 내용을 직접 붙여넣어 주세요. 제목 검사는 형식 확인이며 발급 주체를 인증하지 않습니다. PDF 원본은 서버에 업로드하지 않습니다. 작성일이 없으면 모름으로 두며 과거 기록의 현재 유효성은 다시 확인해야 합니다.

확인한 내용은 페이지 메모리에만 유지하고 새 대화·새로고침·동의 철회 시 비웁니다. 외부 adapter가 연결되면 검토된 `healthNotice.allowReportImport: true`와 유효한 동의가 있어야 해당 내용을 전송합니다. 상세 입출력은 `docs/BACKEND.md`를 참고하세요.

### 0.15.0 응급 안내 우선 표시와 기본 거리

응급 도움은 119 연락, 신고할 위치 요약, 응급처치 항목 선택을 보여줍니다. 지도는 **지도에서 수정**을 누를 때만 생성하고 닫으면 이벤트를 정리합니다. **직접 입력**에서는 기존 주소·장소 검색 후보와 수동 입력을 사용할 수 있습니다. 119 버튼은 카드 스크롤 중에도 상단에 유지합니다.

응급처치 영상은 국내 기관이 공식 채널에 게시한 자료를 사용합니다. 심한 출혈과 열화상은 행정안전부 영상과 질병관리청 국가건강정보포털 자료를 함께 제공합니다. 영상이 있는 항목을 선택하거나 문진 응답의 `emergency.topicId`가 등록된 항목과 일치하면 해당 영상 플레이어가 카드 안에 바로 표시됩니다. 재생은 사용자가 플레이어에서 시작하며, 재생이 되지 않으면 유튜브 원본 링크를 이용할 수 있습니다. 등록된 항목과 일치하지 않으면 다른 처치로 자동 대체하지 않습니다. 팀이 검토한 추가 콘텐츠는 `connectCare({emergencyGuides})`를 통해 연결할 수 있습니다.

검색 카드에는 API 추가 호출 없이 계산한 **직선 약 N m/km**를 표시합니다. 길찾기 이후 유효한 경로 캐시가 있으면 해당 이동수단의 실제 조회 거리를 표시합니다. 거리순 정렬은 일부 기관만 조회한 경로와 직선거리를 섞지 않고 직선거리로 유지합니다. 사용자 위치가 없으면 거리를 만들지 않습니다. 검색·상세정보만으로 경로를 호출하지 않는 정책을 유지합니다.

이번 버전은 응급 도움과 거리 표시 범위입니다. 논의한 로그인, 내 정보·분석서 통합, 계정별 저장과 문진 정보 반영 확인은 이후 작업이며 실제 계정/건강정보 저장은 아직 연결하지 않았습니다.

상단 **로그인 → 약관 및 개인정보 동의**에서 서비스 이용약관과 개인정보 동의 항목을 확인합니다. 약관은 서비스 범위, 계정 이용, 입력 정보·분석서 확인, 선택적 저장과 이용자 권리, 외부 정보 및 응급 상황을 다룹니다. 개인정보 항목은 목적·수집 항목·보유 기간·거부 시 영향을 명시합니다.

실제 카카오 인증과 계정/동의 저장 API는 아직 연결하지 않았습니다. **카카오로 계속하기**는 인증 콜백 연결 전에는 비활성화되며 가입 완료나 서버 저장을 표시하지 않습니다. 이 화면의 선택이 현재 상담의 건강정보 전송 권한을 변경하지 않습니다. 운영 주체/문의처, 외부 AI 제공업체·처리 관계 및 국가, 삭제/백업 정책과 미성년자 정책은 실제 연동 전에 등록·확인해야 합니다. 화면에 적은 보유·삭제 조건에 맞춰 서버도 구현해야 합니다. 현재 건강정보의 외부 AI 전송은 없습니다.

응급 도움, 이전 분석서 가져오기, 문진, 건강정보 처리 안내와 증상 채팅 시작 버튼은 같은 버튼을 다시 눌러 접을 수 있습니다. 문진을 접어도 답변과 단계가 유지되고 분석서 가져오기는 미확정 텍스트를 세션 메모리에 유지합니다. 접을 때 진행 중 PDF 읽기는 취소합니다. 명시적인 취소, 새 대화 또는 동의 철회는 미확정 입력을 비웁니다.

### 0.17.0 내 정보 통합과 목록 전용 보기

상단에는 언어 선택, 내 정보 아이콘, 테마 버튼 순서로 표시합니다. 내 정보는 로그인 안내·건강정보·즐겨찾기로 구성하며 검색 설정과 별도 상담 영역을 두지 않습니다. 분석서는 내 정보의 내용 확인/PDF 버튼으로 엽니다. 건강정보는 내 정보에서 한 번만 입력하고 분석서의 복사·PDF에는 적용한 최신 값을 반영합니다. 수정한 증상과 상담 메모는 유지합니다.

건강정보·분석서는 현재 세션에만 있으며 실제 회원 계정/건강정보/상담 기록 DB 저장은 아직 연결하지 않았습니다. 이 페이지에 과거 상담 목록이나 저장 성공을 임의로 표시하지 않습니다. 다음 연결 대상은 로그인·항목별 동의 상태 조회, 계정 건강정보 조회/수정, 상담별 분석서 저장/조회입니다.

### 0.18.0 목록 카드와 건강정보 반영

**목록만**은 화면 너비에 따라 여러 열의 카드로 표시합니다. 좁은 화면은 한 열을 사용하며 상세정보를 열면 읽기 편한 전체 너비로 전환합니다. 보기 전환 시 기존 검색 조건과 지도 인스턴스를 유지합니다.

문진·대화 API가 건강정보 후보를 전달하면 현재 정보, 답변 근거와 반영할 내용을 대화에서 확인할 수 있습니다. 내용을 수정하고 원하는 항목만 선택해 적용하거나 이번 상담에만 사용할 수 있습니다. 기본 실행에는 임의의 추출 결과를 넣지 않습니다. 실제 LLM 추출과 계정 저장은 연결 전이며, 적용은 현재 페이지의 내 정보만 변경합니다. 직접 편집한 분석서는 덮어쓰지 않습니다.

### 0.19.0 대화 시작 화면

첫 화면은 안내 제목과 넓은 입력창을 중앙에 배치합니다. 동의 전에는 입력창을 클릭하거나 키보드로 진입하면 기존 건강정보 동의 내용이 팝업으로 열립니다. 닫기/Escape는 입력을 시작하지 않으며 동의하면 입력창으로 돌아옵니다. 별도의 ‘증상 채팅 시작’ 버튼은 제거했습니다. 가입 동의 등 다른 동의 문구는 유지합니다.

첫 메시지를 보내면 기존 선택형 문진을 대화 안에서 시작합니다. 첫 메시지는 문진과 함께 유지하며, 문진 완료 또는 건너뛰기 시 연결된 문진 API에 전달할 수 있습니다. 선택 질문 수와 선택지는 기존 데이터 계약을 사용합니다. 마지막 자유 입력이 없어도 문진 완료 요청을 보냅니다. 실제 문진 판단은 백엔드 연결 후 제공됩니다.

입력창의 **+**에서 분석서 PDF 첨부 또는 내용 붙여넣기를 선택합니다. 동의 확인 → 기존 PDF 읽기/내용 확인 → 문진 시작으로 이어집니다. 원본 PDF를 서버에 업로드하지 않는 기존 방식은 유지합니다. 응급 도움은 입력창 밖에 별도로 제공하며 동의 없이 접근할 수 있습니다.

즐겨찾기와 계정별 저장·추천 우선순위는 다음 작업입니다. 이번 버전에 실제 로그인/저장을 추가하지 않았습니다.

### 0.20.0 증상·약국 시작 선택지와 대화 문진

입력창 아래에 기침, 열, 복통과 ‘지금 문 연 약국을 찾고 싶어요’ 선택지를 표시합니다. 클릭하면 화면에 보인 문장 그대로 전달하며, 동의 전에는 선택만 대기하고 동의 후 한 번 전송합니다. 취소하면 자동 전송하지 않습니다. 입력 중에는 선택지를 숨겨 작성에 집중하도록 합니다.

실제 문진 API를 연결하면 첫 입력과 확인한 분석서를 바로 전달하고, 응답으로 받은 질문·선택지를 대화 안에서 표시합니다. 답변 선택, 이전 답변 수정과 ‘여기까지 답하고 찾기’를 지원합니다. 수정한 질문 이후의 답변은 제외합니다. 질문 생성·분기·진료과/응급 판단은 구현하지 않았으며 팀원 1의 API가 제공해야 합니다. API 미연결 상태에는 기존 임시 문진을 유지합니다. 임시 문진도 답변 전에는 건너뛰기를 숨깁니다.

약국 찾기 선택은 병원을 찾는 증상 문진과 구분합니다. API 미연결 상태에서는 사용자가 명시한 ‘운영 중 약국’ 조건으로 기존 검색을 실행하며 의학적 질문을 만들지 않습니다. 실제 API 연결 시에는 해당 문장을 보내 백엔드가 검색 조건이나 필요한 추가 질문을 결정합니다. 특정 약의 복용 가능 여부를 판단하거나 복약 정보를 생성하지 않습니다.

### 0.20.1 입력창 높이 보완

입력창은 한 줄 높이에서 시작하고 작성한 내용에 따라 최대 120px까지 늘어납니다. 첨부·전송 버튼 주변 여백을 줄이고 수동 크기 조절 핸들을 제거했습니다. Next.js 개발 표시(N 버튼)는 devIndicators:false로 숨겼습니다. 개발 오류 출력은 유지합니다.

### 0.21.0 패널 폭 조절과 내 정보 정리

병원 찾기는 대화 40% / 검색·지도 60%, 내 정보는 50% / 50%로 엽니다. 중앙 손잡이를 좌우로 드래그하거나 키보드 좌우 방향키로 조절합니다. 더블클릭은 해당 패널의 기본 비율로 복원합니다. 조절한 비율은 도구별로 현재 페이지에서 유지하며 새로고침하면 초기화합니다. 기존 확대/복귀와 작은 화면의 한 패널 전환도 유지합니다.

건강정보 입력은 내 정보에 한 번만 표시합니다. 이번 상담에는 증상/시점/메모/질문만 표시·편집하고, PDF와 복사는 적용한 최신 건강정보를 함께 가져옵니다. 직접 편집한 상담 내용은 유지합니다. 상단의 별도 로그인 메뉴는 제거하고 내 정보에 비회원 상태와 로그인 버튼을 배치했습니다. 실제 인증과 계정 저장은 아직 연결 전입니다.

넓은 검색 패널에서는 검색 조건을 한 줄에 배치하고, 좁아지면 목록과 지도를 위아래로 배치합니다. 크기 조절로 검색·길찾기 API를 호출하거나 지도를 새로 생성하지 않습니다. 지도는 기존 크기 감지로 중심을 유지해 표시 영역만 갱신합니다.

### 0.22.0 내 정보 단독 화면·언어 선택·즐겨찾기

상단은 내 정보 아이콘, 언어 드롭다운과 테마 버튼으로 정리했습니다. 지도 검색은 대화 검색 결과의 ‘지도에서 보기’로 엽니다. 내 정보에서는 대화를 숨기고 돌아올 때 대화 입력과 스크롤을 복원합니다. 언어는 등록된 번역 리소스 목록에서 선택하며 현재 한국어/영어를 제공합니다. 새 언어는 번역 리소스를 추가해 확장합니다.

로그인 안내는 건강정보와 즐겨찾기를 이어 쓸 수 있는 이점을 설명합니다. AI 답변/로그인 연결 준비 같은 개발 상태 안내는 운영 화면에서 제거하고 문서에서 관리합니다. 실제 로그인은 아직 연결하지 않았고 가입/계정 저장 완료를 꾸며 표시하지 않습니다.

병원·약국 카드, 상세정보와 내 정보에서 별표 즐겨찾기를 추가/해제합니다. 검색의 ‘즐겨찾기만’은 현재 검색 결과를 필터링하며 지도에도 같은 결과를 표시합니다. 대화의 현재 조건에 맞는 운영 중 결과 안에서는 즐겨찾기를 먼저 안내합니다. 즐겨찾기 자체로 진료과나 방문 이력을 추정하지 않습니다.

기본 즐겨찾기는 현재 페이지 메모리에서만 유지합니다. 계정별 조회·추가·해제를 위한 connectFavorites 연결을 준비했으며 실제 인증/DB 저장은 팀원 3 API 연결 후 동작합니다. 저장 기관의 이름/주소만 보관하고 예전 운영 상태를 현재 영업 여부로 재사용하지 않습니다. 내 정보의 ‘찾기’는 해당 기관명으로 기존 검색을 다시 실행합니다.

### 0.22.1 내 정보 정리와 아이콘 정렬

헤더의 내 정보 SVG와 언어·테마를 같은 중앙선에 맞췄습니다. 메인의 별도 ‘지도에서 찾기’ 버튼은 제거하고 대화 검색 결과의 ‘지도에서 보기’를 유지합니다. 응급 도움은 계속 독립적으로 접근합니다.

내 정보는 강조된 로그인 안내, 건강정보, 즐겨찾기만 제공합니다. 검색 설정과 ‘이번 상담’ 영역은 제거했습니다. 건강정보 적용/삭제는 검색 조건을 바꾸지 않습니다. 분석서 편집·복사·PDF는 대화에서 열며, 건강정보를 중복 입력하지 않고 적용한 값을 출력합니다. 실제 인증/계정 저장은 기존과 같이 백엔드 연결 대상입니다.

### 0.22.2 건강정보 배치와 계정 진입

내 정보의 바깥 폼을 전체 너비로 표시하고 건강정보를 PC 2열, 모바일 1열로 배치합니다. 상단 순서는 언어 → 내 정보 → 테마입니다. 계정 버튼과 창 제목은 로그인·회원가입으로 표시합니다. 계정창에 약관 동의와 카카오로 계속하기를 한 흐름으로 배치하고, 독립 동의 메뉴와 동의 확인 후 다시 로그인하라는 중간 단계를 제거했습니다. 문진 동의창의 ‘동의하지 않고 병원 찾기’ 버튼은 제거하고 닫기는 유지합니다.

실제 카카오 인증은 연결하지 않았습니다. AccountDialog의 onContinue가 제공되지 않으면 카카오 진행 버튼은 비활성화됩니다. 인증 담당자는 기존 회원 여부에 따라 needsSignupConsent를 지정하고, 서버에서 가입 동의와 인증을 검증해야 합니다. 동의 선택은 현재 페이지에서만 관리하며 임의의 로그인·가입 완료 상태를 만들지 않습니다.

### 0.23.0 저장·동의·즐겨찾기·응급 도움

- 건강정보는 만 나이(0~120세, 모르면 빈칸), 알레르기, 복용약, 기저질환으로 입력합니다. 저장 전 변경사항은 상담/PDF에 사용하지 않습니다. 화면을 나갈 때 저장/버리기/계속 작성할 수 있습니다.
- 비회원도 내 정보에서 건강정보 입력 동의를 시작합니다. 건강정보 저장은 현재 페이지 메모리에서 확정하는 기능이며 실제 계정 저장은 백엔드 연결 대상입니다. 유효한 같은 처리 동의는 새 대화에서 유지합니다.
- 즐겨찾기는 회원·비회원 모두 병원/약국 합쳐 20곳입니다. 비회원은 페이지 메모리에서만 유지하고 계정으로 이전하지 않습니다. 안내 문구는 내 정보의 로그인·회원가입 블록에만 배치합니다.
- 응급 도움은 모달에서 열립니다. 119, 심폐소생술, AED, 성인 기도폐쇄, 출혈, 화상, 경련 안내를 제공하며 위치 영역은 필요할 때 펼칩니다. CPR 영상 외 새 항목은 출처 있는 텍스트를 제공하고 추가 영상은 검토된 YouTube ID로 연결합니다.
- LLM은 등록된 응급 topicId를 선택하는 연결 구조만 사용합니다. 임의의 LLM 처치 문장이나 영상 ID는 응급 카드에 직접 표시하지 않습니다.
- 새 대화는 상담 내용을 초기화하고 저장한 페이지 건강정보와 즐겨찾기는 유지합니다. 계정 전환 시 이전 계정/비회원의 화면 정보를 비우며 비회원 즐겨찾기를 가져오지 않습니다. 실제 OAuth/DB/LLM 연결 및 실 API 검증은 포함하지 않습니다.

외부 AI 제공업체 미확정 시 필요한 고지·동의 구성과 팀 연결 기준은 docs/BACKEND.md에 정리했습니다. 업체·처리 방식 확정 전 임의의 외부 AI 전송 동의를 활성화하지 않습니다.

### 0.23.1 즐겨찾기 기관 조회 정합성

내 정보에서 즐겨찾기 ‘찾기’를 누르면 기관명과 저장 주소의 지역으로 검색한 뒤 저장한 기관 ID에 일치하는 결과만 표시하고 상세정보를 엽니다. 이름이 같은 다른 지역 기관으로 대체하지 않습니다. 이 조회는 채팅 추천 결과와 분리하며 운영 중 필터를 해제해 진료 종료·운영시간 누락 기관도 확인할 수 있습니다.

운영시간표가 없는 실 기관은 이전 status 값이 남아 있어도 unknown으로 처리합니다. 거리는 공통 계산 함수에서 기기 현재 위치와 해당 기관 좌표로 계산하며 지도 중심이나 검색 위치를 내 위치로 쓰지 않습니다. 실제 GPS/Windows 위치 정확도를 임의로 보정하는 변경은 아닙니다. 새 일반 검색·내 위치·지도 재검색 시 즐겨찾기 기관 고정을 해제합니다.

### 0.24.0 내 정보에서 PDF·로그아웃

대화의 별도 분석서 카드는 제거하고 내 정보에 내용 확인/PDF로 저장 버튼을 배치했습니다. PDF는 기존 분석서 기능을 사용해 저장한 건강정보와 현재 상담 정리 내용을 출력합니다. 저장 전 건강정보는 확정/버리기 선택을 거치며, 분석서 편집본은 유지합니다. 출력 화면을 닫으면 내 정보로 돌아갑니다.

connectAccount 어댑터는 페이지 시작 시 서버의 getSession 응답으로 로그인 상태를 확인하고, 확인된 계정에만 로그아웃 버튼을 표시합니다. logout 서버 성공 후 현재 페이지의 건강정보·초안·상담·분석서·즐겨찾기를 비우며 서버에 저장한 계정 기록을 삭제하는 기능은 아닙니다. 실패 시 로그인 상태와 입력을 유지하고 재시도할 수 있습니다. 실제 OAuth/세션 API는 아직 연결하지 않았으며, 데모 로그인 상태나 브라우저 토큰 저장으로 대신하지 않습니다.

새로고침 정책 제안(백엔드 협의 대상): 회원의 로그인, 저장 동의한 건강정보·즐겨찾기는 서버 세션/DB에서 복원하고 진행 중 문진·대화도 유효한 상담 세션에서 복원하는 방향으로 변경했습니다(0.24.1). 새 대화에서만 현재 상담을 명시적으로 비우고 계정 저장 정보는 유지합니다. 비회원 정보는 현재 페이지에서만 유지합니다. 현재 계정 건강정보 저장·조회 API는 미연결이므로 새로고침 후 건강정보가 자동 복원되는 단계는 아닙니다.

### 0.24.1 개발용 로그인 시험과 새로고침 정책

새로고침은 현재 문진·대화를 복원하고 새 대화에서만 초기화하는 방향입니다. 현재는 메모리 기반이므로 실제 복원은 상담 세션 저장·조회 API와 보관 범위/기간 안내를 연결해야 합니다. 건강정보나 채팅 원문을 브라우저 저장소에 임의로 넣지 않았습니다.

카카오 계정 없이 로그아웃 UI를 시험하려면 이 버전을 적용하고 npm run dev로 실행한 뒤 브라우저 F12 → Console에서 실행합니다.

```js
await medicalDev.login()
```

내 정보를 열면 개발용 계정의 로그아웃 버튼이 보입니다. 버튼을 눌러 비회원 화면으로 돌아가고 현재 페이지 정보가 비워지는지 확인할 수 있습니다. 다른 개발 계정은 await medicalDev.login('second')로 확인합니다. 테스트 계정 전환 시 현재 대화와 건강정보 입력은 초기화됩니다. 동일 개발 계정의 즐겨찾기는 현재 페이지의 모의 저장소에서만 유지합니다.

실제 카카오 인증, 인증 토큰 저장, 서버·DB 저장은 하지 않습니다. 개발용 로그인은 새로고침하면 해제됩니다. npm run build / npm start의 운영 화면에는 medicalDev가 등록되지 않으며 이전 Node 서버 정적 허용 목록에도 개발용 모듈을 추가하지 않았습니다.

## 0.24.2 변경

내 정보의 내용 확인 버튼을 제거했습니다. 건강정보 PDF에는 저장한 만 나이, 알레르기, 복용 중인 약, 기저질환만 표시하며 내 정보 화면에서 바로 인쇄/PDF 저장합니다. 저장 전 변경사항은 저장·버리기·계속 작성으로 처리합니다.
문진 조작은 입력창에서 질문 영역으로 옮겼습니다. 접으면 현재 단계와 이어하기가 남고, 제출한 답변 요약에는 답변 수정 버튼을 표시합니다.
회원의 진행 중 상담을 새로고침 후 복원하는 기능은 향후 API 연결 범위입니다. 비회원 상담은 새로고침 시 초기화합니다. 이번 버전은 저장·복원 DB를 추가하지 않습니다.
